# AMBS Platform — قواعد العمل الدائمة

## اللغة (قاعدة أولى)
- **كل الردود باللغة العربية** طوال المحادثة، دون استثناء، حتى في الرسائل التقنية الطويلة.
- الأوامر والكود وأسماء الملفات والمعرّفات التقنية تبقى كما هي.
- لا يُتحوَّل إلى الإنجليزية أبدًا في منتصف المحادثة.

## فصل المشروعين
- المشروع A: نظام ABMS على Notion لشركة الدعم الفني — مؤجَّل.
- المشروع B: منصة AMBS المبرمجة (SaaS عربي متعدد المستأجرين) — هو العمل الحالي.
- لا يُذكر في README المنصة اسم الشركة ولا التكييف ولا المصاعد ولا الدعم.

## طريقة العمل
- منذ 2026-11-21 (بموافقة المالك): Claude يكتب الكود ويدفعه إلى فروع العمل مباشرة، وCI على GitHub Actions هو مصدر الدليل. أوامر PowerShell للمالك تبقى خطوة خطوة، وفقط لما يلزم جهازه (البيئة المحلية، النشر، الأسرار). التفاصيل وخطة الإطلاق في مهارة `ambs-review-engineer`.
- التحقق بالدليل (بصمات SHA256، نواتج الأوامر)، وإصلاح أي خلل يُكتشف.
- لا اختراع بيانات؛ ولا ادعاءات أوسع من الآلية (يُقال «مرجّح، لم يُتحقق»).
- عرض التصميم على المالك قبل أي تنفيذ؛ وشرح كل توصية على حدة: أهميتها وخطرها وصحة اتجاهها وقيمتها؛ والبحث في الأنظمة الاحترافية قبل القرارات الخطرة.

## Git وGitHub
- لا تغيير على main ولا PR ولا دمج دون موافقة صريحة؛ المالك ينشئ PR ويدمجه بنفسه.
- Claude يدفع إلى فروع العمل القصيرة فقط (`feat/...`، `fix/...`)، لا إلى main، ولا force-push على فرع ليس من إنشائه.
- التدقيق حسب الخطورة: الصرامة الكاملة للأمان والعزل والهوية والجلسات والمال والهجرات؛ الميزات العادية اختبارات + CI + مراجعة واحدة.
- لا تُطبع كلمات المرور أبدًا؛ `.env` و`userlist.txt` و`credentials.json` تبقى محلية.
- الحزمة الأصلية v4 لا تُمسّ.

## الاختبارات والهجرات
- لا يُعدَّل اختبار ليمرّ؛ تغيير متطلب يختبره اختبار قائم يحتاج قرار المالك ويُوثَّق علنًا.
- الهجرات ثابتة بايتًا ببايت؛ أي تغيير في هجرة جديدة فقط.
- كل هجرة تغيّر بنية يثبّتها المشغّل يرافقها تحديث صريح لأساسه بالصرامة نفسها، يُعرض على المالك قبل التشغيل.
